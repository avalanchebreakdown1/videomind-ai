# API v1 — transcription and direct educational rewriting

`write_document=true` selects the direct transcript rewrite by default. `verify=false` remains the default: writing uses the completed raw transcription directly. Explicit `verify=true` enables the optional second ASR pass first.

The worker rewrites bounded transcript chunks using the same installed Ollama model, with no extraction/outline/separate review calls. Word contains technical notes and source attribution without inline uncertainty flags. Contextual corrections and excluded generated code remain in `rewrite_audit.json`. Model-reported corrections are not a complete semantic diff or external fact checking. `quality_state=needs_review` and `externally_fact_checked=false` describe this unreviewed output; they are not processing failures.

`GET /api/v1/jobs/{id}/document` returns Word; `format=json` returns the direct structured document (sections with paragraph/code blocks), `txt` readable notes, `quality` the processing limitations, `rewrite-audit` contextual repairs/exclusions, and `source-chunks` exact source character spans and context. Fixed filenames only. Unknown formats return 422; incomplete jobs return 409; absent reports return 404. Public artifact lists advertise existing files only.

Historical jobs remain readable. `knowledge`, `evidence`, and `content-gate` formats serve their original legacy reports if present. Direct rewriting does not generate those reports. The standalone CLI can explicitly run the historical workflow with `--pipeline legacy`; the normal API uses direct rewriting.

Failures retain the raw transcript and diagnostics; no final Word is served. Every attempt writes a new directory and checks original source hashes. Writing does not establish factual accuracy or complete lecture coverage.

Implemented local API. Launch `python -m uvicorn videomind.api:create_app --factory --host 127.0.0.1 --port 8000`. Interactive forms and OpenAPI are at `/docs` and `/openapi.json`. Run one server process.

SQLite jobs store a UUID, state, stage, progress, cancellation flag, internal source payload, sanitized metadata, safe error and timestamps. Files live under `storage/jobs/<UUID>/`; upload names never become paths. Public responses exclude internal payloads and paths. Artifact routes serve fixed filenames. The implemented Next.js proxy is described below; a dedicated artifact table remains unimplemented. Source-integrity hashes are retained with processing reports.

| Endpoint | Request | Response |
|---|---|---|
| GET /api/v1/health | — | 200 worker availability, source limits and defaults; does not check/load models |
| POST /api/v1/jobs | multipart: required authorized=true, exactly one youtube_url or file; verify=false/true and write_document=false/true (both default false; writing does not enable verification) | 202 job resource and Location |
| GET /api/v1/jobs/{job_id} | — | 200 state, stage, progress, warnings, safe source metadata and available artifacts |
| GET /api/v1/jobs/{job_id}/transcript | kind=raw/verified, format=json/txt, download=false/true | 200 preview JSON or attachment; verified requires verify=true on submission |
| GET /api/v1/jobs/{job_id}/verification | — | 200 evidence, disagreements, uncertainty and coverage report; 409 until requested review finishes |
| GET /api/v1/jobs/{job_id}/document-source | format=json/txt | 200 separate technical-writing source with exclusions/statuses, or annotated TXT; 409 until a verification job finishes, 404 for older jobs without preparation artifacts |
| GET /api/v1/jobs/{job_id}/document | format=docx/json/txt/quality/rewrite-audit/source-chunks (legacy reports when present) | 200 Word attachment or generated text/JSON/reports; requires a completed write_document job |
| POST /api/v1/jobs/{job_id}/cancel | — | 202 cancellation requested; 200 if already terminal |

States: queued -> running -> completed/failed/cancelled; queued jobs can be cancelled immediately. `cancel_requested` remains true until worker acknowledgement; the database terminal state becomes cancelled even if completion races with the request. Stages include queued, ingesting, normalizing, transcribing, stitching, optional verifying and terminal state. Verification jobs allocate progress through 75% to ingestion/transcription, then up to 99% to review; completion sets 100%. Progress is indicative, not a time estimate. Checks run between stages/chunks/review passes; active inference/FFmpeg completes its current operation before cancellation. Terminal states are immutable. Retries require a new submission; interrupted running jobs fail on startup and queued jobs survive.

With `verify=true`, a different server-configured ASR checkpoint reviews selected normalized-audio sections. The original transcription directory is never edited. Word statuses, original candidate outputs, crop ranges, comparison edits, rechecks and source hashes are written in a separate verification directory. Public job `verification` includes state, coverage fraction, uncertain/failed section counts and `audio_verification_performed`. Review may finish as `completed_with_errors`; inspect this summary and report rather than treating job completion as proof of accurate transcription. The top-level `audio_verified` remains false, and unchecked words are explicitly marked. All default models share Whisper ancestry; agreement is not ground truth.

`kind=verified` JSON contains unchanged original `text`, separate `annotated_text`, per-word statuses and uncertain audio spans. TXT contains uncertainty markers and unresolved-section notes. A verification setup failure marks the job failed with code `verification_failed` but leaves its completed raw transcript downloadable. Section-level ASR failures preserve evidence, produce uncertainty and appear in the review summary; they never silently replace text. Verification was not requested on existing jobs; use the standalone `videomind verify` CLI to review their transcription directory into a separate output directory.

New raw runs record `stitching_version=overlap_alignment_v2`, `stitching.json` boundary candidates/decisions and raw `stitching_issues`. New verification JSON records `comparison_version=scientific_nfc_case_sensitive_v2`, `source_stitching_version`, `source_stitching_issues` and per-word `audio_reviewed`. Case/exponents/leading decimals/math punctuation remain significant. Unchecked assembly ambiguity is flagged rather than silently marked supported. Old run files and reports are never rewritten; legacy raw runs can be reconstructed with the standalone `restitch` command into a new directory, then verified anew.

New reviews additionally create `document_source.json`/`.txt`: a conservative editorial copy excluding clear greetings/channel chatter, with an audit of removed spans and retained source statuses. It is explicitly `is_final_document: false` and `fact_checked: false`. Ambiguous/disputed wording and technical examples remain for later review. Cleanup does not edit either transcript or serve as audio verification. `/document` serves the separate written artifact for jobs requesting writing.

Errors: 404 unknown job/missing artifact; 409 transcript not ready/document unavailable; 413 upload limit; 422 invalid URL, authorization, source or output parameters; 429 queue full; 503 worker unavailable. Error envelope: `{"error":{"code":"invalid_source","message":"..."}}`. Validation errors also identify field locations. Worker failures appear in the job's `error` field with safe codes such as `download_failed`, `download_timeout`, `restricted_video`, `duration_limit`, `invalid_audio`, `processing_failed` or `interrupted`. A completed ASR run with no recognized words carries a warning in the transcript; it does not establish silence or accuracy. Attachment filenames are generated and include the job UUID.

Source rules: require confirmation of authorization. Accept only HTTP(S) YouTube host forms, canonicalized to an 11-character video ID; reject credentials, explicit ports, fragments, arbitrary hosts, live links and playlist parameters. Validate again in the downloader. No client-controlled downloader flags, credentials, cookie imports, plugins or access bypass. Remote requests and redirects are HTTPS-only with public-IP pinning and allowlisted hosts. Select direct audio-only formats; unsupported/challenge-dependent videos fail with upload fallback guidance.

Defaults: 256 MiB source/request-file limit plus 64 KiB multipart overhead, four-hour media duration, 900-second total download deadline, 20-second socket timeout, five queued/running jobs. Whole bodies are bounded before multipart parsing even without Content-Length; file bytes are checked again while copying. Upload content is probed in the worker and known media-container demuxers are enforced. Input Content-Type/extension alone is never trusted. Completed storage is retained until manually managed; no total disk quota or automatic retention yet.

Only loopback access is supported. Backend Host headers must be localhost/127.0.0.1/[::1]; browser Origin, when present, must be `http://localhost:8000` or `http://127.0.0.1:8000`. CLI clients without an Origin are allowed. The Next.js frontend uses the bounded same-origin proxy below. No authentication, multi-user authorization or public deployment support is provided. Selectable writing styles remain planned; the interface uses technical educational notes.

## Local Next.js integration

`GET /api/v1/health` reports worker availability, source limits and default processing mode, without model/network calls. A completed raw transcript is previewable/downloadable while its document is still being written, or after cancellation/failure when completed transcription evidence exists. Partial primary transcripts are never served as completed artifacts. Worker stage `transcription_completed` differs from terminal job `completed`; `document_completed` means the final job update is pending.

The Next.js frontend proxies only fixed job/health routes through `/api/...` to the configured loopback FastAPI origin. It validates actual loopback Host/Origin values, streams bounded uploads, forwards download bytes/content disposition, refuses upstream redirects and exposes sanitized connection errors. It does not broaden backend TrustedHost or origin rules. Deep links `/?job=UUID` reopen an existing local job; no job IDs, media paths or model secrets are inserted into public global listings.
