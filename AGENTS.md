# VideoMind AI contributor instructions

- Build incrementally. Milestone 1 is a local audio-to-raw-transcript CLI. Do not start Milestone 2 until its acceptance checks pass and the user requests further work.
- M2 ingestion is authorized: YouTube/audio uploads, local jobs/API and integration with M1. Report results before continuing. A dedicated frontend and M3 verification remain outside this ingestion pass.
- M3 is now authorized: separate, selective audio verification using a distinct ASR checkpoint, controlled disagreement tests, evidence and uncertainty artifacts. Preserve every original transcript/evidence file byte-for-byte. Do not start document writing or UI work in this pass.
- Follow-up document policy: prepare a separate source copy excluding clear greetings/channel chatter, with exclusion evidence; retain technical examples, caveats and disputed wording. Final writing must be formal technical education, with separately reviewed factual claims. Preparation is not fact verification or final document generation.
- Current gate: fix the two confirmed comparison/stitching defects and report remaining M1–M3 issues before advancing. Preserve unit case, superscripts/subscripts, leading decimals and mathematical punctuation. Keep old runs immutable and validate them with their recorded stitching version; rebuild only into a new directory with an integrity audit.
- Subsequent explicit user authorization includes M4/M5: local Ollama knowledge extraction, independent technical writing, evidence-linked review and professional DOCX export, with controlled content-integrity tests. Earlier writing deferrals/gates above describe historical passes. UI remains outside this pass; outstanding M1–M3 accuracy/reliability issues remain documented rather than implicitly closed.
- Writing outputs must remain separate from transcripts. Audit source hashes and persist model requests/responses/settings/digest. Validate IDs/quotes/schema, disclose unsupported claims, uncertain/unchecked audio and excessive source similarity in Word. LLM source-consistency review is not external scientific fact verification; require educator review before publication.
- Content-quality acceptance is now explicitly open: the full lecture draft contained real factual/relevance errors despite successful processing. Withhold flagged text from normal reading outputs with a complete audit, preserve all candidates/transcripts, and distinguish separately reference-checked editorial revisions from automatic pipeline results. Do not declare M4's educational-quality goal complete from processing tests alone; see `DOCUMENT_QUALITY_REVIEW.md`.
- Keep services in `backend/videomind/services/` and dependencies injectable for offline tests. No network or model downloads in the default tests.
- Run `python -m pytest` after changes; run the opt-in real ASR smoke test when changing audio or inference integration.
- Use `env -u PYTHONPATH .venv/bin/python -m pytest` to isolate inherited ROS packages. FastAPI TestClient needs normal local sockets; if sandbox thread wakeups hang, request command escalation instead of weakening transport controls.
- Stream audio through FFmpeg to disk. Decode only bounded chunks into ASR memory. Preserve raw model outputs, timestamps, settings, and failure state.
- Do not describe primary ASR, timestamp stitching, or LLM text review as independent audio verification. Never fill gaps by inventing speech.
- Use environment variables for settings. Do not commit credentials, user media, model weights, or generated artifacts.
- No arbitrary URL fetching, access-control bypass, shell interpolation, or unbounded subprocesses. Keep strict YouTube canonicalization, audio-only selection, public-IP-pinned HTTPS with redirect/host checks, and playlist/live rejection. Do not enable browser cookies, credentials, plugins or remote JS components automatically.
- Preserve unrelated files. Do not make system-wide changes without permission. Keep documentation explicit about implemented versus planned functionality.
- Report files, implemented behavior, executed tests/results, limitations, and the next milestone.

- Latest user direction: skip M3 audio verification in the normal document workflow for now. Writing must not implicitly enable verification; retain explicit opt-in compatibility and historical evidence. M4 rewriting/DOCX remains necessary; its existing multi-stage implementation has not yet been replaced by a single-pass rewrite.

- Latest writing authorization supersedes the earlier default writing/gate policy: use direct transcript-to-technical-notes rewriting by default, with one installed Ollama model, no separate extraction/outline/review passes, and no inline uncertainty markers. Use context to repair recognisable technical wording and complete explanations. These are editorial completions, not recovered speech or independently verified facts; never manufacture measurements, dates or citations. Preserve raw transcripts and historical outputs, keep source hashes/model calls and a separate correction/exclusion audit. Keep the former pipeline explicitly available as `--pipeline legacy` for historical compatibility. Test the entire existing lecture and inspect the resulting document; do not equate processing success with perfect content.

- The latest user request authorizes the Next.js frontend, FastAPI integration, local server startup, browser integration tests, and fixes for observed failures. Earlier UI deferrals are historical. Preserve the backend's local-host/origin controls through a bounded, fixed-route loopback proxy. Keep offline browser fixtures separate from the production app. Resolve and test known regressions before reporting UI acceptance; never interpret passing software checks as proof that all generated educational content is factually error-free. Selected reference-backed Python editorial rules must be separately audited, without altering transcripts.

- Git workflow: the user authorizes commits and pushes of completed, tested project improvements to their configured GitHub repository. Use focused commits with descriptive messages, inspect staged files for credentials/generated artifacts, and report the commit and push result. Never force-push or include unrelated changes. If the remote or authentication is unavailable, complete the local commit and report what is needed to upload it.
